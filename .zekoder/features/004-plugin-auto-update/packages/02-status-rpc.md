## Context

Owns contract **builtin-plugin-update-status** (contracts.md). Studio owns this API; zekoder-plugins feature 023 consumes it from its plugin `server.handle` handlers as `paseo.pluginUpdates.status("zekoder")`. The field list is final; implement exactly what contracts.md lists. Read `docs/rpc-namespacing.md`, `docs/protocol-compatibility.md` and `docs/protocol-validation.md` first. Schemas stay pure (no `.transform/.catch/.preprocess`); new fields are optional; zod-aot output is generated by `pretypecheck`/`prebuild` and never edited.

Naming: new types use the `BuiltinPluginUpdate*` prefix. Never reuse or extend the existing `PluginUpdate*` source-update schemas (`messages.ts` ~L1473-1508, ~L6720-6745).

Templates to copy, same file each:
- Request/response: `plugin.source.status.request` — `packages/protocol/src/messages.ts:1510` (request), `:6701` (response), registered in the unions near `:3223` and `:6824`.
- Feature flag: `pluginSourceUpdates` — `messages.ts:3607-3608` (schema), `packages/server/src/server/websocket-server.ts:1839` (advertise).
- Session handler: `packages/server/src/server/session.ts:2485-2494`.
- Client method + gate: `getPluginSourceStatus` — `packages/client/src/daemon-client.ts:5525-5545`.
- `PaseoApi` — `packages/client/src/index.ts:484` (interface) and `createPaseoApi` `:547`.

Server-side reach: plugin `server.handle` handlers get `paseo: PaseoApi` (`packages/plugin/src/server/contracts.ts:10`), built by `createPaseoApi(daemonClient)` in `packages/server/src/server/plugins/plugin-process.ts:275` over the IPC transport. Adding `pluginUpdates` to `createPaseoApi` covers it, but only if that IPC `DaemonClient` sees `server_info.features.pluginUpdates`; otherwise the gate throws. A test proves it (Tasks).

Injection seam for that test: bootstrap dependencies (`packages/server/src/server/bootstrap.ts` ~L484, beside `builtinPlugins`) and `createTestPaseoDaemon` options (`packages/server/src/server/test-utils/paseo-daemon.ts` ~L54/~L107) gain optional `builtinUpdateStatus`, passed to `new PluginService(...)` (~L622). 03 later supplies the real updater adapter there when none is injected.
